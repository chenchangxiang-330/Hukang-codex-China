# Hukang 奶白天空蓝 · 原生营养 UI V2

本轮把确认的设计落到原有 React Native + Expo + TypeScript 页面，不使用 WebView。起点为 `codex/ui-v1` 的 `0f72fa36d50d22819ca34f23ec010f3a47cefcc9`，工作分支 `codex/nutrition-ui-v2`，PR 目标 `codex/ui-v1`。开始时远端 V1 比 main 领先 4 个提交、落后 0 个。

视觉参考为交付的 `hukang-nutrition.html` 与原生落地 Markdown。HTML 仅作为不受信任的布局、颜色、文案和交互参考，没有执行或移植其脚本。

## 页面与操作

| 页面 | 本轮实现 |
| --- | --- |
| 今天 | 原 Logo、奶白纸感、能量圆环、三列宏量、完整营养入口、最多三条有数据依据的发现、餐食速览、常驻拍一拍 |
| 饮食记录 | 横向日期、前后日期、四餐分组、同日期营养摘要、食物详情与实际份量调整 |
| 今日营养 | 更深的雾蓝底色、94×50 返回按钮、七类展开卡片、目标/范围/限制型进度、添加糖双参考线、未知与小计提示 |
| 拍一拍 | 餐食估算和包装食品两个入口；相机/相册照片预览、保留描述、份量/日期/餐次、结果及状态反馈 |
| 食品详情 | 沿用原始单位营养表与库存操作，增加“如果吃完这份”只读预览；已食用操作明确提示真实饮食存储未接入 |
| 食品库 / 我的 | 原搜索、筛选、库存、资料编辑、导出、AI 设置回调；颜色统一天空蓝 |

`src/ui/tokens.ts` 统一奶白 `#FFFDF7`、暖白 `#FFFEFA`、天空蓝 `#96CAE9`、强调文字 `#386F95`、正文 `#30485C`。`assets/paper-grain.png` 是一次生成的静态透明颗粒，低透明度叠加，无逐帧生成或外部图片服务。原 App 图标未变。

Dock 使用 `expo-blur@57.0.3`（当前 Expo 57 bundledNativeModules 推荐版本）与 `BlurTargetView`，背景模糊、半透明暖白、细高光、阴影与可减少动态效果的选中滑块。Android 使用 `dimezisBlurViewSdk31Plus`，旧版本提供半透明降级。依据 [Expo 57 官方 BlurView 文档](https://docs.expo.dev/versions/v57.0.0/sdk/blur-view/)。这不是系统原生液态玻璃的实现声明。

Dock 位于安全区内部、距边缘留空；正文预留浮动操作与 Dock 的滚动空间。拍摄/核对/详情隐藏 Dock，键盘显示时也隐藏。Android 键盘弹出后收缩内容区，并测量、滚动当前输入框使其保持在键盘上方；同一处理复用于原有食品录入和核对表单。保留系统字体缩放，能量数值与圆环可换行；原生字体放大时圆环同步增大。返回恢复上个页面的滚动位置和所选日期。Android 验收发现的 320dp / 1.5 倍系统字号日期按钮越界已修复：空间不足时月份独占一行，前后日期按钮等宽排列。

## 业务边界

生产入口 `SimpleApp` 仍调用原 `useSimpleApp()`，新页面只通过现有 controller 进入扫码、建档、OCR、核对、保存、库存及导出。没有改动 controller、SQLite schema、领域模型、图片处理、OCR 证据、模型文件、联网权限、包名或签名策略。

- 正式营养适配器 `productionNutrition` 返回未接入、空记录及空个人目标。没有默认 1285 kcal、2000 kcal 或示例食品。保存个人目标或饮食会明确返回未接入，不能假报成功。
- 完整演示仅在 `tests/ui-preview/nutrition-demo.ts`。生产 `src/` 不导入演示适配器。它以一个可订阅内存快照驱动三页，刷新清除；不依赖或调用 SQLite/库存保存。拍一拍内的模拟入库只是演示确认反馈，不改变真实或模拟摄入。
- 餐食相机与相册使用已有 `expo-image-picker`。照片与可选文字形成同一次不可变请求；切换页面、照片或文字会使旧请求失效，拍照按钮有重入保护。正式餐食 AI 未接入。固定区间样例只出现在明确标记的开发预览。
- 包装外观 AI 匹配未接入，不把“身份尚未确认”解释为“食品库没有同款”。提供现有扫码、手动输入条码、本机食品库查找。扫码后仍进入原包装→营养表→离线 OCR→人工核对流程。
- 包装入口新增正面照片目前仅在当前页面预览；扫码建立身份后，仍须在原流程保存包装原图。未实现自动把这张预览图移交持久食品草稿，不宣称已有自动匹配。
- 营养表采集、旋转裁剪、原图/原文/人工修订分离继续由原实现负责。核对文案明确整包净含量与每份大小不同。
- 自动抠图未接入，展示原图及说明。真实产品“加入库存”仍调用原库存事务；“已食用”与库存分开。饮食预览不先写入，演示确认有稳定操作 ID 并去重。

## 数据规则

`src/features/nutrition-v2/model.ts` 提供独立展示接口：`Fact`、`Food`（食品 ID、资料版本、原始能量、每份与包装规格分开）、`Entry`（日期/餐次/实际数量/单位）、`Targets`、`NutritionAdapter`、`Total`。不引入数据库迁移。

- 数值保留单位、来源、已确认/估算/未知状态；估算支持上下界。未知不是 0，已知小计不是完整全天；混合估算保留区间，不取中点。
- `contribution` / `total` 统一换算与聚合。kJ 只在展示贡献阶段换算一次，原值保留。每100g、每100mL、每份独立；无密度不换算 g/mL，整包不自动等同于每份。
- 总糖、添加糖、纤维和碳水不再次相加计算热量。标签只有“糖”不会填入添加糖；配料糖源不推断克数。
- 只有完整且确认的单值才显示精确百分比，分母明确。范围与限制型不显示“全部达标”。添加糖有 25g 理想参考与 50g 上限两条线；已知小计本身超出时仍明确“有数据缺失”。
- 钠与食盐当量引用同一数值，不重复累计。维生素未录入不代表没有摄入或缺乏；饮水入口明确未接入。
- 未来接入点：真实按日期饮食 repository、个人目标配置持久化、餐食图片+文字 AI gateway、可靠包装身份匹配、原图可追溯的抠图服务。长周期趋势可复用营养键与资料版本，不需要把计算散在 JSX 中。
