# Hukang 0.5.7 · 资料、目标与餐食确认

基于 `534fcabbc1c29f209eb93aa214f6241eb9fbc2c8` / 0.5.6，在 `codex/nutrition-ui-v2` 增量修改。SQLite schema 8，不重置数据库，不改包名；参考仓库未修改。版本 0.5.7 / versionCode 18。

## 实际修改

- 个人资料自动保存，返回和重启可恢复；保存串行但不阻断输入。照片相册多选、追加、单张预览/删除，保存在私有目录，引用独立于个人资料导出和食品照片。兼容既有单张引用。
- 生成目标后进入独立草案页。返回不发请求、不应用；资料或照片变化使旧草案失效。只有确认才应用，目标管理仍在「我的 → 个人参考目标」。
- AI 设置分别选择餐食、包装/营养表、个人资料、体检照片的发送授权，与已验证的服务地址一起存入系统安全存储。连接测试不等于业务授权；旧版没有持久授权的连接需在设置中补选一次。恢复连接不发请求，更换地址清空待保存的授权范围，失败保留旧活动连接；删除连接取消旧请求并删除授权。日常页面仅在缺少配置/授权/能力时显示短提示。
- 餐食页仅保留照片、拍照/相册、选填描述和估算按钮。结果直接展示营养值/范围和未知状态、日期时间、1 份，营养编辑是次级入口。确认保存复用既有事务/操作编号；不再要求份量按钮或额外确认。保存后的记录仍可编辑份量、日期和餐次。
- 继续保留营养表 API 识别、扫码、人工核对、食品库、库存、导出、区间统计和本地数据。未扩展 AI 能力或自动抠图。

## 请求与资料边界

统一 Chat Completions。支持的图片模型仍为官方 `deepseek-flash` / `qwen3-vl-plus`；自定义及未知图片能力不假装支持。多张照片作为同一 user content 中的全部 image_url 发出；不存在只发送第一张的分支。照片删除后不在请求集合中。无图目标推荐仍可用。

核实来源：[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)、[通义千问图像限制](https://help.aliyun.com/zh/model-studio/vision)（2026-11-09）。官方支持多图，限制分别包含 DeepSeek 600 张、48 MiB 请求体，Qwen Base64 250 张、DashScope 域名 16 MiB 请求体。本 App 沿用更小的原生网络边界：**最多 6 张、每张上传副本 < 4,000,000 bytes、完整 UTF-8 JSON 请求体 ≤ 6,000,000 bytes**，不是宣称服务商只有这些额度。超过任一上限整次拒绝，不分批收费、不漏图。保留现有最长边 2048、元数据清理和有限次压缩；Qwen 额外检查最短边和比例。原图不改写。

资料、照片选择/恢复不自动发送；只在生成或估算操作发送。体检照片不进入普通导出。模型文本仍当不可信数据校验，未知不当零，范围不取中值，AI 来源/不确定性保留。实际模型阅读小字的效果待真实服务与手机验收。

## 验证状态

本机 TypeScript、160 项 Node 测试、29 项 Python 测试、格式和资源检查通过。Node HTTPS 模拟服务实际收到多图 JSON；验证授权恢复/切换/撤销、全部图片/超限不发送、旧单图兼容、自动保存顺序、草案失效、未知和事务防重复。共享 RN 浏览器检查 35 + 18 + 1 项通过，新增交互覆盖多选/追加/预览/删除、草案跳转/返回/失效、直接营养展示/修改和一份保存。
