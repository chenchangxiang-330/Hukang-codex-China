# 0.5.6 手机验收清单

先看同目录交付说明中的签名核对结果。只有与手机现有安装签名相同，才能覆盖安装并保留原数据；签名不符时保留原 App，不卸载、不清数据。没有旧版的独立测试设备可以安装测试包。

1. **重新录入**：打开包装食品，选择营养表照片后返回首页；再次进入包装食品，应直接开始新流程，没有“继续补录”弹窗。食品库、库存和已有饮食数量不变。同次录入的结果返回照片、再返回结果，当前内容仍在。
2. **进度**：在“我的”确认个人目标已设置。查看同一日期的首页、记录和营养详情；确认食用、修改份量、改日期、删除后，三处数值同步。估算范围有上下限填充；“小计”说明部分缺失，未知显示“—”。展开后只有贡献明细，没有重复总量和长公式。
3. **营养表 API**：在设备内配置支持图片的服务和模型，密钥不要发到聊天或截图。进入包装食品的“直接识别营养成分表”，分别试拍照和相册；首次按提示确认发送范围。核对每 100g / 每 100mL / 每份、kJ / kcal、g / mg 是否保持原表，不清楚的值应为空。点选营养行修改后保存，没有条码也可建档；再按实际食用份量记录。
4. **失败**：断网、无效测试配置、取消识别时应显示失败/取消，不能显示保存成功或新增食品。重新配置连接后，下一次识别使用新地址和模型。不要连续点击产生重复收费请求。
5. **原有功能**：离线扫描已存食品；打开食品库、库存，增减库存不改变摄入；导出食品资料与个人数据，检查原记录仍在。
6. **屏幕与返回**：使用系统大字体，试表格数值输入和滚动；确认键盘、返回按钮和 Dock 不遮挡操作。Android 系统权限拒绝后可回到流程，再授权或使用相册。

本轮自动化的 API 成功/失败检查使用模拟服务；真实服务准确度、真实相机反光/模糊照片、具体手机兼容性须在设备上完成。营养表不自动回退至旧 OCR。
