# 0.5.5 营养条显示修复

本轮基于 `5690044e078b1a59519fa84ff4bfc16793d968f8` / 0.5.4（15），保留现有分支和原有未跟踪 `.DS_Store`。App 递增到 0.5.5 / versionCode 16，SQLite 仍为 8。

## 原因与修正

0.5.4 的 `NutrientProgress` 只有在计算得到比例时才创建整条横槽。未保存饮食、未设个人目标、未知或部分数据缺失，都会返回空比例，导致首页只显示四行文字。统计规则需要保守，但不应因此移除基础视觉结构。之前的验收检查了四个项目标题，却没有断言四条底槽存在，这是验收遗漏。

- 首页蛋白质、今日卡路里、脂肪、膳食纤维始终保留细底槽；展开的营养详情使用同一组件。
- 未设目标显示“未设置目标”，在第一项未设置的参考旁提示“我的 → 个人参考目标”。设置仍统一位于“我的”，不新增首页设置入口。
- 收紧营养行的留白，并将路径提示合并进已有说明行，保证默认 390dp 短屏的“拍一拍”完整位于 Dock 上方；文字与按钮最小点击尺寸保持原值。第一轮 Android 截图暴露了新增条形结构挤占首屏空间，已据此补充实际边界断言，旧自动化通过结果不再等同于视觉验收完成。
- 没有记录、全部未知、部分缺失或只有估算范围时不绘制填充，不生成假的 0% 或精确达标率；读屏明确“暂不计算进度”。底槽不是加载动画。
- 已确认数值与有效目标按实际量填充，例如隔离测试的 50g / 100g 为一半；已确认 0g、超目标、估算单值维持各自语义。目标范围保留区间标记；超过目标最多填满并保留实际摄入量和超出量。
- 修正浏览器 `protein-partial` 夹具，让它实际包含缺失数据。此前名为 partial 的场景没有加入缺失食品，不能算作有效的部分数据展示验证。

未改变食品、目标、营养累计、数据库、AI、库存和导出逻辑；没有向正式记录写入演示数据，也不设置统一的 100g 或 2000kcal 默认目标。

## 当前功能边界

0.5.4 已有的食用保存/修改/删除、统一统计、食品与库存分离、扫码/离线 OCR/人工核对、导出、个人资料/目标草案、统一 API 调用及安全存储继续保留。餐食照片要求模型具备图片能力，估算经人工确认后才计入摄入。

真实服务商成功响应尚未使用真实密钥实测，自动测试使用模拟 HTTP。BiRefNet 实际模型下载、推理和透明贴纸待接入；实体设备和旧签名覆盖升级仍待验证。完整边界见 [0.5.4 交付](Redesign1103.md)。

手动目标可通过“我的 → 个人参考目标 → 手动修改目标”填写，加入草案后再确认应用；不需要 API。首页的摄入量来自已保存饮食，AI 预览未确认前不会计入。没有可靠个人参考时保留底槽和未设置提示，不擅自给所有用户填入同一目标。
