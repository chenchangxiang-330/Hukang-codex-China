# Hukang China Phase 3.1 测试与验收记录

本文件定义“商品身份查询 → 用户确认 → 本地营养表 OCR → 绑定保存”这一条流程的验收边界。它不把 provider 的模拟响应、类型检查或按钮存在当作真实联网验收。

## 证据等级

| 等级 | 含义 | 可以声称的内容 |
| --- | --- | --- |
| `unit` | 纯 TypeScript/SQLite 测试，使用固定 mock | 校验、去重、超时、降级、事务和数据不串线符合契约 |
| `integration-mock` | App/provider 边界接入 mock HTTP transport，服务响应不出测试进程 | 页面状态和错误映射符合统一响应协议；不能证明供应商真实命中 |
| `release-offline` | Release APK 断网安装并执行 | 本地扫码、OCR、手动建档、已保存记录可离线使用 |
| `release-network` | 实际 APK → Hukang HTTPS 服务 → 已授权供应商，使用测试条码 | 只能记录本次环境、条码和配额下的真实身份返回，不能推断全国覆盖率 |
| `device-camera` | 真实设备相机拍摄条码并完成闭环 | 才能声称相机取景链路已验证；图片解码或手动输入不能替代 |

没有对应证据文件时，报告必须写“未验证”。模拟数据不能写成“供应商已命中”。

## 必测状态矩阵

### 本地优先与联网开关

| 场景 | 预期请求 | 预期结果 |
| --- | --- | --- |
| 本地已有完整食品档案 | 0 | 直接打开本地档案，不触发 provider |
| 本地已有商品身份、营养缺失 | 0 | 显示身份，进入拍摄营养表；不重复查商品 |
| 本地未收录、联网查询关闭 | 0 | 保留条码，允许手动填写身份并继续 OCR |
| 本地未收录、联网查询已启用 | 至多 1 次 | 成功则显示身份待核对；失败则保留草稿并允许手动填写 |
| 用户取消/切换条码 | 0 次新的旧商品写入 | 旧响应不得覆盖当前商品 |
| 重复帧/重复点击 | 至多 1 次有效查询 | 不重复消耗额度或创建商品 |

每个 mock transport 都应记录调用次数、目的地和请求体摘要。请求体不得含图片 URI、图片字节、OCR 原文、营养记录、SQLite 内容、API key 或用户档案。

### provider 业务错误

身份服务必须把 HTTP 成功与业务成功分开。至少覆盖下列可观察状态：

- `found`：返回并通过字段/条码校验的名称、品牌、规格；状态仍为“身份待核对”。
- `not_found`：服务商明确表示没有记录；不得显示“商品不存在”或食品安全结论。
- `offline`/`timeout`：断网或超时；保留条码，允许手动建档。
- `not_configured`：服务端未配置凭据或客户端未启用；App 仍可启动并继续离线流程。
- `unauthorized`：密钥无效/权限不足；不得重试或把错误当作未收录。
- `rate_limited`/`quota_exceeded`：限流/额度不足；不得并行切换其他供应商。
- `malformed`/`identity_conflict`：字段缺失、类型错误或返回条码与请求不一致；丢弃身份候选并保留条码。

供应商返回的营养字段（如果存在）不得自动写入用户营养表；用户拍摄的 OCR 证据仍是唯一的营养标签来源。第三方图片 URL 不自动下载。

### 草稿与绑定闭环

使用固定测试条码（不进入生产库）覆盖：

1. `not_found → identity draft → nutrition OCR evidence → draft/confirmed save`：同一个草稿 ID、条码查询键和证据 ID 在每一步保持一致。
2. 服务命中 → 用户确认身份 → 拍摄营养表：顶部仍显示商品名、规格、条码；取消拍照不清除身份草稿。
3. 查询失败 → 手动填写身份 → 保存：失败原因不能覆盖用户已填写字段。
4. 已保存记录重启后扫码：只查询 SQLite，不重新调用 provider 或 OCR。
5. 已有无条码食品补绑：建立唯一关联；冲突时拒绝覆盖并显示已有记录。
6. 同条码新包装：建立新的营养标签/修订和来源，不静默替换旧证据。
7. 删除食品：条码索引和该记录引用的证据按数据库事务清理；不能影响其他食品共用文件。

断言原始 OCR JSON、原图、处理图和 `FoodRevision` 未被用户编辑覆盖；人工确认值只写入 review/identity revision。

## 网络观察

真实联网验收必须记录：

- APK SHA-256、applicationId、versionCode/versionName、签名证书指纹。
- 设备型号、Android/API、测试时间和是否启用飞行模式。
- App 实际请求的固定 Hukang HTTPS 主机、方法、业务路径和状态码。
- 上游供应商只在服务端出现；客户端不能指定 URL、供应商或 key。
- 调用次数、耗时、超时、额度响应以及返回字段摘要（脱敏）。
- 断网重试时没有照片、OCR 文本、营养记录或本地数据库外传。

没有抓包或服务端审计证据时，不得声称“没有上传”。只能写“代码边界未配置上传，运行时网络观察未完成”。

## 真实食品清单

准备约 20 件大陆在售食品，分别保存条码、包装正面照片和营养表照片的本地路径及来源说明。测试 fixture 不得打包进生产食品库。每条记录至少记录：名称/品牌/口味/规格匹配、provider 状态、字段缺失、错误商品、超时、调用次数和费用。没有获得供应商授权、测试额度和用户提供素材前，清单只可标记为“待执行”。

## 当前限制

- mock provider 只能证明接口契约和失败降级；不能替代聚合数据或 TianAPI 的真实请求。
- 真实供应商授权、API key、额度、HTTPS 部署地址和缓存/展示许可必须单独配置；密钥不得提交 Git 或粘贴到聊天。
- 相机物理取景、连续帧去重和设备断网闭环需在实际 Android 设备执行；相册图片解码不等同于相机验收。
- 本文件不批准购买、充值、签约、公开部署或建立共享食品数据库。
