# Hukang 0.5.0：本机饮食闭环与照片识别

从 `codex/nutrition-ui-v2` / `810863f448f9dc25b1ed786eda12355b877a7d10` 继续，原有 `.DS_Store` 未跟踪文件保留。React Native、Expo、奶白天空蓝、纸感、玻璃 Dock、明显返回控件沿用。

## 使用入口

- **拍一拍 → 餐食估算**：文字描述，或拍照/相册生成本机上传副本。配置 API 并确认发送内容后调用真实服务；没有 API 时可以选「手动记录这一餐」，不会声称识别照片。
- **核对 → 确认记录**：修改名称、按标注基准修改营养、选择日期/餐次/实际份量；明确确认后才写入 SQLite。保存中阻止重复操作和返回，成功后显示已保存。
- **记录 → 点击食物**：查看保存时快照，修改名称、营养、份量、日期、餐次；删除需要二次明确确认。今天、记录、营养详情共享一个订阅数据源。
- **今天或营养详情 → 个人参考目标**：保存已有目标到本机，留空表示未设置，不预填 2000 kcal。
- **拍一拍 → 包装食品**：优先扫码/手动条码和食品库。可主动发送正面副本取得名称/品牌候选，核对后仅用于查找；名称相同不自动认定同款。条码未命中后的原包装页也能调用同一服务，已填写的名称/品牌不会被候选覆盖。营养表仍走原离线 OCR、旋转裁剪、重新识别和人工核对。
- **食品详情 → 记录食用 / 加入库存**：分别确认，饮食增删改不会改变库存。

## 数据与迁移

`src/services/nutrition/` 增加纯 SQL 仓库、共享订阅适配器、原生文件适配和显式字段校验。现有 `sqliteFoodStore` 增量迁移 v6 → v7；失败回滚，不提前提升版本，不删除旧业务表。

- `nutrition_entries`：按本地日期、餐次索引；JSON 保存营养基准、已确认保存时间、食品版本、独立快照、份量、来源、区间、不确定性。
- `nutrition_operations`：唯一操作标识与事务一起提交。记录删除后保留提交标识，迟到回调不复活旧记录；另一笔操作可再次记录同一种食品。
- `nutrition_settings`：个人目标；没有设置时为空对象。
- `nutrition_photo_cleanup`：复制失败/中断和删除后的清理队列，只处理该饮食 ID 的独立照片目录。仍被记录引用的照片不会删除。
- `simple_package_hints`：保留人工使用过的 AI 名称候选与来源，和 OCR 原始证据分离。

饮食与 `foods` / `simple_inventory` 没有级联关系。食品库修改、删除不改写饮食历史。照片保存前复制到 `nutrition-photos/{entryId}`，不继续引用可能被删的食品库或缓存照片。所有营养/操作/来源字段经过显式白名单，不存储 API 请求、请求头、密钥或会话配置。

确认保存不等于营养已经验证。AI 数字仍为估算；用户修改数值移除旧范围，标记「用户修改 · 未经独立验证」。未知为 null，与已知 0 区分。保留每 100g、每 100mL、每份或描述实际食用的 1 份基准，不猜测密度；kJ 只换算一次。总糖不充当添加糖，不重复累计纤维、糖或食盐当量。

个人导出 schemaVersion 2 增加饮食快照、目标和包装候选来源，可选包含独立饮食照片。食品资料分享包仍不包含个人饮食或库存。仍不提供 App 内导入恢复。

## 真实 API 与图片

统一 `AiService` 处理连接、餐食和包装，使用 HTTPS / Bearer / 非流式 Chat Completions。预设 DeepSeek `deepseek-flash`、千问北京 `qwen3-vl-plus`；自定义兼容服务保持文字请求，未验证的模型不开放图片。地域、模型权限与费用在设置页说明。文字测试成功不代表图片已经实测。

本轮重新核对的官方资料（2026-11-01）：

- [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)：root `/chat/completions`、`image_url` Data URI，Flash 视觉，48 MiB 请求包上限。
- [千问兼容接口](https://help.aliyun.com/en/model-studio/compatibility-of-openai-with-dashscope)：地域密钥须匹配；工作空间专属域名和旧 DashScope 域名均有文档支持。
- [千问视觉接口](https://help.aliyun.com/en/model-studio/qwen-vl-compatible-with-openai)、[图片约束](https://help.aliyun.com/en/model-studio/vision)：Qwen3-VL 支持 Base64；当前文档原图 20 MB / Data URI 20 MB 限制高于应用上限。

应用上传副本统一 **4,000,000 字节**；Base64 解码长度再次校验。完整 UTF-8 JSON 请求同时限制 **6,000,000 字节**（JS 与原生网络层），比上述官方上限更严格。不得自动重试；取消/超时只停止等待，不承诺未计费。模型输出、图片文字和 OCR 均为业务数据，不执行指令。包装输出单独校验，拒绝额外条码/营养字段。

Android `UploadImageProcessor` 在独立单线程上：检查实际格式/尺寸/原始字节，最多读取 50,000,000 字节原图；拒绝超过 1.2 亿像素或单边 40,000 的图；先按边界采样到最多 2048 边/400 万像素，再解码、纠正 8 类 EXIF 方向、合成白色透明背景，最多四次缩放/JPEG 编码。支持本机解码器可读取的 JPEG/PNG/WebP/HEIF/HEIC/AVIF；不能解码时明确重选，不承诺所有手机支持所有格式。不会将超限副本发送给服务。

上传副本不保留 EXIF/GPS/XMP，不覆盖相册原图。预览期间留在应用缓存，重选、显式清除和组件销毁清理；进程中断遗留缓存超过 24 小时后在下次处理初始化清理。持久饮食照片先独立复制，再按记录生命周期管理。OCR 的原图/无损处理图、旋转裁剪和证据目录完全沿用独立流程。

密钥继续仅在进程内存临时使用；清除/换配置取消旧请求与迟到结果。无记住密钥、自动上传或后台同步。扫码、OCR、食品库、库存、人工核对和导出继续离线。

## 验证与交付边界

自动验证包含真实 SQLite 迁移/回滚、幂等保存、历史快照、份量/单位/日期、目标、照片失败清理；统一 API 的本地 HTTPS 模拟服务以及错误/取消/超时/迟到结果；共享原生组件的隔离浏览器回归。Android 云端验收将实际安装最终 APK，空页面截图与隔离测试中人工录入的记录截图分别标记。

没有提供真实 API Key；不在聊天索取。真实服务商计费/文字/照片效果、实体手机镜头与扫码、厂商系统等仍需用户在手机上主动实测。自动抠图、云同步、社交、长期趋势及饮水记录未扩展。

构建前只检查了 Actions secret 的名称，没有读取签名私钥。仓库没有配置持续签名，原有临时私钥不可获得，因此新包仍为独立测试签名。不能声称可覆盖旧版保留数据升级；不卸载、清库或更改包名绕过。最终 APK、证书、SHA-256、安装与验收证据另见本轮 Android 交付文档。
