# Hukang 0.5.3：界面精简与个人蛋白质进度

基于已交付 0.5.2 与其后文档提交，在 `codex/nutrition-ui-v2` 增量修改。运行时代码提交：`328a2dca96d3df104ec484522ea686e63b88e39c`。原有 `.DS_Store` 未追踪文件保留，没有改动参考仓库。

## 本轮改动

- **今天**：移除宣传口号、热量环和重复营养摘要。保留紧凑能量、蛋白质目标进度、碳水/脂肪数值、完整营养入口、最近一餐与拍一拍。只有有依据的钠/添加糖提醒才显示，最多一条。没有饮食记录时只显示真实空状态与记录入口。
- **记录**：紧凑日期选择、单行能量与营养详情入口；早餐/午餐/晚餐/加餐依次展示。食物点开优先调整份量，名称、详细营养、来源、日期和餐次按需展开，保留确认删除。
- **营养详情**：默认仅展示类别核心值及未知/估算/缺失状态。点击展开目标、来源和组成；蛋白质/纤维用目标语义，碳水/脂肪保留区间，钠/添加糖保留上限语义。保留日期，设置目标返回后保留已展开项目。
- **拍一拍**：先选择餐食或包装食品，文字与手动填写为次级入口。拍照/输入与人工核对分步显示，保存前只预览，保存成功后才显示成功。包装食品继续优先扫码或本地查询，包装正面 AI 辅助按需打开。
- **我的**：个人参考目标、AI 设置、数据导出、关于四项列表。导出按需展开；食品库、库存仍从食品库入口使用。
- **保存反馈**：原生验收发现修改日期/餐次后的提示在视口外，已移到对应保存按钮旁。继续编辑时清除旧提示，错误也显示在对应操作处；补充视口内可见及日期同步回归。
- **布局**：保留奶白、天空蓝、纸感和玻璃 Dock，按实际 Dock 高度为滚动内容预留空间。返回按钮保持至少 48dp，正文和点击区域未为塞内容而缩小。

## 统计与数据

沿用 SQLite v7、原食品快照、个人目标和统一 `total()`；本轮没有数据库迁移或数据重置。新增的 `targetProgress()` 只解释同一份统计结果，不另存摄入量。

| 状态 | 蛋白质展示 |
| --- | --- |
| 已保存已确认数值，个人目标已设 | 实际摄入 / 个人目标；细进度条 |
| 未设目标 | 设置目标；不显示虚假进度 |
| 部分缺失 | 已知小计、数据不完整；不画精确进度 |
| 全部未知 / 无记录 | 未知 / 尚未记录；不伪装成 0% |
| 完整的估算点值 | 约数、估算标记和近似条；无精确百分比 |
| 估算区间 | 保留区间；不强行变成一个百分比 |
| 超过目标 | 实际值保留，条封顶，中性标注超出量 |

100g 只出现在隔离测试中，不是生产默认目标。未确认 AI 结果不参与汇总；确认后的 AI 结果仍为估算。修改份量、日期、餐次和删除通过原存储与订阅同时更新三页。未知不当零。

2. 今天、记录、食品库、我的切换；真实空页面没有演示数据。个人目标未设时没有虚假进度。
