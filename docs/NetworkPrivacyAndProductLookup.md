# 国内商品身份查询与网络隐私边界

商品查询是可选能力，默认关闭。用户在商品身份页明确启用本次查询后，客户端
最多为当前规范化条码发起一次请求；重新扫描才会开始新的查询。关闭开关、拒绝
授权、服务未配置或断网时，本地扫码、PaddleOCR、手动建档、SQLite 记录和历史
查询继续工作。

## 唯一允许的请求

客户端只向构建时配置的 Hukang 控制 HTTPS origin 的固定路径发送：

```text
POST /v1/food-identity/lookup
{
  "rawValue": "包装上读到的原始数字字符串",
  "gtin": "已校验的 GTIN",
  "lookupKey": "14 位规范化查询键",
  "format": "EAN_13 | EAN_8 | UPC_A | UPC_E"
}
```

不发送照片、图片 URI/字节、OCR 原文、bounding box、营养数据、食品数据库、
账号标识、设备标识、API key 或任意上游 URL。客户端不能选择供应商；服务器用
部署 secret 调用一个经过批准的国内供应商，并只返回名称、品牌、规格等身份字段。
服务默认未配置，不会主动连接供应商。

## 本地保留规则

供应商候选只在当前身份草稿中暂存。用户明确确认后，保存的是用户核对后的身份；
身份与营养证据分别写入 SQLite，来源和确认时间保留。若来源是
`mainland_service` 而缓存授权不是 `allowed`，数据库拒绝长期保存，避免把公开
查询结果误当作可再分发数据。未知授权不会被“用户点击确认”自动变成第三方授权。

服务状态必须区分：本地命中、国内服务命中、未收录、断网/超时、未配置、无效密钥、
限流/额度不足、响应格式错误和身份冲突。失败不能丢掉条码，也不能显示“商品不存在”
或食品安全结论。

## 运行时限制

- `INTERNET` 只为上述可选国内身份查询保留；`ACCESS_NETWORK_STATE`、模型下载、
  OTA、遥测、广告、远程配置、云 OCR 和在线 AI 均不启用。
- OCR 模型、原图、处理图、OCR 原文、营养解析、人工修改、SQLite 和修订历史始终
  使用本地实现；商品身份查询不能触发图片或文字上传。
- 固定 HTTPS origin 必须通过正常证书校验，禁止 HTTP、任意重定向上游和客户端密钥。
- 没有授权、部署地址、供应商密钥和测试额度时，不得宣称真实联网命中。
