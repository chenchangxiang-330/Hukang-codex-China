# Hukang 国内商品身份服务（最小后端骨架）

这是条码商品身份查询的固定边界，不是中央食品库，也不接收照片、OCR
文字、营养表、用户食品档案或账号数据。客户端只能 `POST` 到固定路径：

```text
POST /v1/food-identity/lookup
{
  "rawValue": "6900000000014",
  "gtin": "6900000000014",
  "lookupKey": "06900000000014",
  "format": "EAN_13"
}
```

服务端会重新校验格式、长度、校验位和 UPC-E 展开；供应商的结果只允许返回
名称、品牌、规格等商品身份字段。响应不会包含图片 URL，也不会接受客户端
提供的上游 URL、供应商名称或 API Key。重复请求、限流、超时和无配置会返回
明确错误码，客户端应降级到手动建档和本地 OCR。

当前仓库只包含 `server/vendor-adapter.mjs` 边界，默认返回
`SERVICE_UNAVAILABLE`（原因是未配置经过授权的供应商）。没有 API Key、供应商
合同、部署地址或限额时，不能宣称真实联网查询已经可用。部署时必须在进程
外注入一个固定、经过审核的供应商 adapter；密钥只放部署平台的 secret，不能
放进 APK、GitHub 源码、日志或构建产物。公开部署前还必须加访问控制、限流、
每日/总额度上限、HTTPS 证书和审计日志脱敏。

运行本地骨架：

```sh
node server/hukang-food-service.mjs
```

默认只监听 `127.0.0.1:8787`；它不会主动连接任何供应商。生产环境应由国内
HTTPS 反向代理提供固定服务地址，未配置服务不影响 App 的离线扫码、OCR 和
本地食品记录。

## 候选供应商审批状态

本项目只保留一个 provider 边界，不在 App 同时接入多家供应商。当前候选是：

- 聚合数据商品条码接口：官方文档声称可按条码查询商品基础字段；实际支持
  格式、个人开发者申请/用途审核、HTTPS 端点、展示、长期缓存、离线读取和
  费用条件尚未取得书面确认。
- 天聚数行商品条码接口：官方文档声称可返回商品身份字段；相同的申请、
  计费、字段授权、缓存/再分发和 HTTPS 细节仍待书面确认。

在取得当前官方协议和授权前，二者均不得配置为生产 adapter。优先建议先向
聚合数据索取商品条码接口的书面授权与 HTTPS/缓存条款；若不满足 Hukang 本地
身份档案的用途，再评估天聚数行。没有真实凭据和测试额度，不进行供应商真实
请求，也不记录命中率或费用。
